Continue building the MVP CRM app we have started.

Implement the complete operational workflow and the lightweight automations described below.

This CRM is for a coffee distribution business. It is an internal operational CRM, not a full ERP. Keep the system simple, practical, modular, and demo-ready.

Core workflow:

customer -> lead/request -> order -> delivery planning -> driver delivery -> documentation upload -> accounting approval -> ready for invoicing

Important principles:
- Keep this as an MVP
- Do not overbuild
- Do not add advanced ERP logic
- Do not add GPS tracking
- Do not add map-based route optimization
- Do not add real accounting integration
- Do not add advanced inventory management
- Use demo data only
- Use English in the UI
- Make the app responsive
- Make the driver view mobile-friendly
- Keep the code modular and easy to extend

Roles:
- admin
- operations
- sales
- driver
- accounting

Role behavior:
- admin has full access
- operations manages delivery planning and driver assignment
- sales creates customers, leads, and orders
- driver only sees assigned deliveries and can update delivery status/documentation
- accounting gives final approval and marks records as ready for invoicing

Customer priority:
Customers must have priority class:
- A
- B
- C

This A/B/C priority must be visible in the UI and used in planning, dashboards, and sorting logic.

- urgency

- status

Order source:
- phone

Order items:

- quantity
- unit price snapshot
- line total

Order statuses:
- new
- incomplete
- blocked
- planned
- out_for_delivery

- approved
- cancelled

Add automatic validation:
An order should be marked incomplete/blocked if it is missing:
- customer
- delivery address
- at least one product
- requested delivery date

Blocked/incomplete orders must not be moved to planning until required fields are completed.

Add simple prioritization based on:

Allow manual override at all times.

6. Driver workflow

Build a mobile-friendly driver view.

Driver can:
- see assigned deliveries
- open delivery detail
- mark “Arrived”
- upload delivery proof photo / delivery note photo
- add deviation note
- submit documentation

Deviation options:
- damaged_goods
- missing_items
- delayed_delivery
- not_delivered
- other

Important:
A delivery cannot be considered complete without documentation upload.

When documentation is uploaded:
- validate that a file exists
- store upload timestamp
- store uploading user
- link the document to the delivery
- automatically move the delivery/order to awaiting_accounting_approval
- create an activity log entry

7. Accounting approval workflow

Final approval is given by accounting, not operations or manager.

Use this exact flow:
1. driver uploads documentation
2. delivery/order moves to awaiting_accounting_approval
3. accounting reviews the documentation
4. accounting can approve or reject
5. if approved:
   - order status becomes approved
   - delivery status becomes approved
   - invoice_triggered = true
   - invoice_triggered_at is set
   - record appears in Ready for Invoicing list
6. if rejected:
   - status becomes rejected or needs_review
   - accounting can add a rejection note
   - operations can follow up

Important:
Do not build real accounting software integration.
This is only invoicing basis logic.

Add an accounting summary panel for each approval item showing:
- customer
- order number
- products
- quantities
- delivery date
- driver
- uploaded documentation
- deviation note if any
- current status

8. Ready for invoicing workflow

Create a “Ready for Invoicing” list.

It should show records approved by accounting:
- customer

- delivery date
- total amount
- invoice_triggered status
- invoice_triggered_at

- accounting approval user

This is not actual invoicing. It is only a clean list for accounting to use as invoicing basis.

==================================================
ADDITIONAL LIGHTWEIGHT AUTOMATIONS
==================================================

Implement these simple automations:

1. Duplicate customer check
When creating a customer, warn if another customer exists with similar:
- company name
- phone
- email
- address

Do not block creation completely; just show a warning.

2. Auto-fill order from customer profile
When a customer is selected in an order:
- auto-fill default delivery address
- show payment terms
- show discount level
- show priority class A/B/C
- show contact person

3. Auto-create delivery from order
When an order is valid and ready for planning, automatically create a delivery record in the unassigned planning queue.

4. Automatic delayed status
If planned delivery date has passed and the delivery is not approved, mark or flag it as delayed.

5. Automatic deviation follow-up
If driver reports a deviation, automatically flag the delivery for operations follow-up.

6. Automatic accounting summary
When a delivery reaches awaiting_accounting_approval, generate a clean summary for accounting.

7. Automatic archive behavior
Once an order is approved and invoice_triggered is true, remove it from active operational lists and keep it available in history / ready for invoicing.
